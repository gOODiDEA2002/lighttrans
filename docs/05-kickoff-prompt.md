# 编码会话开工提示词

用途：每次给编码会话（Opus）派任务时，复制以下模板并替换任务编号。配合三道防线使用：项目 CLAUDE.md 自动加载厂规、一次只派一个任务、每任务验收后提交一次 git commit。

## 派活模板

```
执行 docs/04-implementation-plan.md 中的任务 T1。
开始前：先完整阅读 docs/ 下全部设计文档和项目 CLAUDE.md，用几句话向我复述 T1 要做什么、验收标准是什么，确认后再动手。
过程中：遇到文档未覆盖的决策点，停下来问我，不许自行决定。
结束时：对照 T1 的验收标准逐条给出验证证据，等我确认。未经我确认不得开始 T2。
我确认通过后：将本任务的改动提交为一个 git commit，提交说明格式为"T1: 一句话概括"。
```

## 使用注意

1. 任务编号依次替换为 T1 至 T10，顺序不可跳跃。
2. 建议每完成两三个任务就开新会话继续，新会话会重新完整加载项目规则。
3. T4（翻译服务）需要提供真实的接口地址、模型名与 API Key 做流式验证；T7（历史记录）需要本机已登录 iCloud；T9（开机自启）需要一次注销重登验证。详见实施计划第 3 节。
4. 验收时对照实施计划中该任务的"验收标准"逐条核对证据（构建输出、运行行为、文件落盘），不必通读代码。
5. 任一任务跑偏时，用 git 回退到上一个任务的提交点重来，不带病推进。
